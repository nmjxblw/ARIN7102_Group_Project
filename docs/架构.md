## 一句话结论

这个仓库不是几块彼此独立的代码，而是一条从“数据预处理与增强”到“训练数据/模型资源”再到“embedding 检索与推荐”，最后落到“CLI / FastAPI 应用入口”的流水线。

主链路可以概括为：

1. 数据预处理模块把原始药物信息加工成增强药表
2. 检索推荐模块在增强药表上构建语义检索和排序能力
3. 服务层把召回、重排和业务打分封装成可调用接口
4. 训练数据和 BERT 模块并行支撑标签预测与离线实验

## 按链路看：这些模块怎么接起来

### 1. 数据加工层

起点是 `match_data_preprocessing/`。

这里先把原始药物数据、疾病键、成分信息和补全症状信息整理成增强药表。这个表不是中间可有可无的附件，而是后续推荐系统的核心输入资产。

关键产物：

- `enhanced_drug_table_v1_structured.csv`
- `disease_keys.json`

### 2. 数据集与模型资源层

训练和评估相关 JSON、生成数据、本地 `ClinicalBERT` 文件属于这一层。

它们主要服务于：

- `deployment_module/bert_main.py` 的训练和预测
- 一些离线实验与标签预测链路

这层不是推荐系统在线主入口，但它提供了旧链路和实验链路所依赖的数据与模型资源。

### 3. embedding 检索与推荐层

在增强药表之上，检索推荐模块开始工作。

核心连接方式是：

1. `prepare_drug_dataframe()` 把增强药表整理成可检索字段
2. 生成 `disease_key_list`、`symptom_list_normalized`、`semantic_text`
3. `DrugEmbeddingEngine` 把 `semantic_text` 编码成向量
4. `drug_knn_retriever.py` 和 `recommendation_pipeline.py` 基于这些向量做召回和排序

这一层的本质是把“清洗好的结构化药表”变成“可搜索、可召回、可排序的候选系统”。

### 4. 应用整合与服务入口层

最上层由 CLI 和 FastAPI 把前面几层封装成真正可运行的系统。

旧入口主要是：

- [launcher_main.py](/Users/jayden/Desktop/7012%20datamining%20and%20text/project_march/ARIN7102_Group_Project/app/launcher_module/launcher_main.py)
- [bert_main.py](/Users/jayden/Desktop/7012%20datamining%20and%20text/project_march/ARIN7102_Group_Project/app/deployment_module/bert_main.py)

这条线更偏向训练和标签预测。

新入口主要是：

- [service.py](/Users/jayden/Desktop/7012%20datamining%20and%20text/project_march/ARIN7102_Group_Project/app/fastapi_module/service.py)
- [router.py](/Users/jayden/Desktop/7012%20datamining%20and%20text/project_march/ARIN7102_Group_Project/app/fastapi_module/router.py)
- [pipeline_design.md](/Users/jayden/Desktop/7012%20datamining%20and%20text/project_march/ARIN7102_Group_Project/docs/pipeline_design.md)

其中 `service.py` 是关键拼装层，它负责把增强药表、embedding、召回器、重排器和业务分数组装起来，最终暴露成统一推荐能力。

## 串起来看的一条完整流水线

可以按下面这个顺序理解整个项目：

1. `yinan` 先做数据预处理和增强药表
2. `PeaHaWf` 提供训练数据、生成数据和部分模型资源
3. `yaoja123` 在增强药表上构建 embedding 检索与推荐实验能力
4. `nmjxblw / z c` 把这些模块整合成 CLI、FastAPI 和项目主干

也就是说，项目的实际连接不是“几个人各写一块互不相干的代码”，而是：

数据资产先被加工出来，再被检索推荐模块消费，最后被服务层暴露成完整应用；而 BERT 与训练数据模块在旁边提供标签预测和离线实验支持。

## 你可以主负责到哪一层

如果按文件主作者口径回答，你更适合把自己的主责任限定在：

- 增强药表之上的 embedding 编码
- 向量检索 / 候选召回
- 推荐实验链路

不宜把以下部分说成你主导完成：

- 原始药物数据的清洗与增强药表构建
- BERT 训练数据和本地模型资源准备
- 整个项目的大部分框架、部署与服务封装

更准确的说法是：

你主要负责推荐系统中“embedding 检索与实验”这一层，它依赖前置的数据加工资产，并被上层服务模块进一步包装成可调用接口。
